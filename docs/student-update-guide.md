# คู่มืออัปเดตงานสำหรับนักศึกษา

ใช้กับเว็บไซต์ https://csgok.sfinsulations.com/ และ repository charoensin-group

## เริ่มงานทุกครั้ง

1. อ่าน [ทะเบียนหน้าเว็บ](page-status.md) เพื่อดูรหัสหน้า URL และสถานะล่าสุด
2. ค้นหาหน้าเดิมใน WordPress และตรวจว่าเป็นส่วนในหน้ารวมหรือไม่ ก่อนสร้างใหม่
3. ตรวจ Issues ว่ามีคนรับงานหน้านี้แล้วหรือยัง ถ้ามีให้ใช้ Issue เดิม
4. สร้าง Issue แยกตามรหัสหน้า ระบุผู้รับผิดชอบและแผนวันที่เริ่มก่อนลงมือ
5. คำว่า “ยังไม่มีลิงก์” หมายถึงยังไม่มี URL ในข้อมูลส่งมอบ ต้องตรวจสอบก่อน ไม่ใช่คำสั่งให้สร้างใหม่

## ใช้สถานะให้ตรงกัน

| สถานะ | ใช้เมื่อ | ค่าใน JSON |
|---|---|---|
| รอตรวจสอบ | ต้องค้นหาหน้าเดิมหรือยืนยันขอบเขตงาน | link_not_provided |
| ยังไม่ได้ทำ | ตรวจแล้วว่าต้องทำใหม่ แต่ยังไม่วางแผนเริ่ม | not_started |
| วางแผนทำ | กำหนดวันเริ่มแล้ว แต่ยังไม่เริ่มจริง | planned |
| กำลังทำ | เริ่มทำงานจริงแล้ว | in_progress |
| ติดปัญหา | ทำต่อไม่ได้ ต้องระบุปัญหาและผู้ที่ต้องช่วย | blocked |
| มีลิงก์แล้ว · รอตรวจรับ | มีหน้าให้ดู แต่ยังไม่ได้ส่งให้ผู้บริหารตรวจ | existing_pending_review |
| รอผู้บริหารตรวจสอบ | ส่งลิงก์ให้ผู้บริหารแล้ว รอความคิดเห็น | pending_executive_review |
| ต้องแก้ไขตามความคิดเห็น | ได้รับข้อแก้ไขแล้ว ต้องระบุรายการ | changes_requested |
| ผู้บริหารอนุมัติแล้ว | มีหลักฐานการอนุมัติ ระบุวันที่และผู้ตรวจ | done |

วันเริ่มตามแผนและวันเริ่มจริงแยกกัน งานในอนาคตยังไม่เป็น “กำลังทำ” ไม่บันทึกอนุมัติเอง และไม่ปิด Issue ขณะรอตรวจ

## สร้าง Issue งานแต่ละหน้า

เข้า **Issues → New issue** ตั้งชื่อ เช่น `[01] ปรับปรุงหน้าแรก` แล้วคัดลอกแบบฟอร์มนี้:

```markdown
## ข้อมูลงาน
- รหัสหน้า:
- หน้า / หมวด:
- ผู้รับผิดชอบ:
- สถานะ:
- ลิงก์หน้าเดิม:
- WordPress Page ID / ตัวแก้ไข / template:
- ไฟล์ต้นฉบับหรือ Pull Request:
- วันที่วางแผนเริ่ม:
- วันที่เริ่มจริง:
- วันที่คาดว่าจะส่งตรวจ:

## งานที่ต้องทำ
- [ ] ระบุงาน

## เกณฑ์ตรวจรับ
- [ ] เนื้อหาครบตามขอบเขตที่ตกลง
- [ ] ตรวจบน desktop และมือถือ
- [ ] ลิงก์และฟังก์ชันที่เกี่ยวข้องทำงาน
- [ ] บันทึกลิงก์ผลงานและสถานะล่าสุด
```

ระบุชื่อผู้รับผิดชอบในเนื้อหาก่อน หากตั้ง Assignee ไม่ได้ ผู้ที่มีสิทธิ์ค่อยเพิ่มให้ ไม่ต้องเปิด Issue ซ้ำ

## อัปเดตทุกวันที่มีความคืบหน้า

เขียน Comment ใหม่ใน Issue เดิมก่อนจบวัน ไม่ลบประวัติวันก่อน ใช้วันที่ตามเวลาไทย ระบุ “ไม่มีความคืบหน้า” ได้ถ้าติดปัญหา

```markdown
### อัปเดตวันที่: วว/ดด/ปปปป
- ผู้บันทึก:
- สถานะ:
- วันนี้ทำแล้ว:
- งานที่เหลือ:
- ปัญหา / ต้องการความช่วยเหลือ:
- ลิงก์ผลงาน / commit / Pull Request:
- แผนครั้งถัดไปและวันที่:
```

GitHub บันทึกผู้เขียนและเวลาของ Comment ให้ แต่ยังควรใส่วันที่ทำงานในข้อความ เพื่อแยกวันที่รายงานย้อนหลังออกจากวันที่ทำจริง

## อัปเดตทะเบียนให้เห็นภาพล่าสุด

เมื่อสถานะเปลี่ยน ให้อัปเดต **ทั้งสองไฟล์** ในงานเดียวกัน:

- [docs/page-status.md](page-status.md): แถวของรหัสหน้านั้น ใส่สถานะ ผู้รับผิดชอบ วันที่ และงานถัดไป
- [data/sitemap.json](../data/sitemap.json): รายการที่มี id ตรงกัน อัปเดต status และ notes พร้อมข้อมูลวันที่ที่ทราบ ห้ามเดาหรือแก้รายการหน้าอื่น

ค่า planned, blocked และ changes_requested เป็นค่าที่แนะนำในคู่มือนี้ หากเริ่มใช้ให้เพิ่มความหมายใน status_definitions ของ JSON ด้วย
บันทึก URL เป็นลิงก์กดได้ ใช้ branch และ Pull Request สำหรับงานพัฒนา พร้อมอ้างอิง Issue; หากแก้เอกสารตรงผ่านเว็บและโครงการอนุญาต ให้กดรูปดินสอ → แก้ไข → Commit changes พร้อมข้อความสั้นบอกสิ่งที่เปลี่ยน

## ส่งตรวจและจบงาน

1. ตรวจผลงานตามเกณฑ์ก่อนส่ง
2. เมื่อส่งลิงก์จริงแล้ว บันทึกวันส่ง ช่องทาง และผู้ตรวจที่เกี่ยวข้องตามข้อมูลที่ทราบ พร้อมเปลี่ยนสถานะเป็น “รอผู้บริหารตรวจสอบ”
3. หากมีข้อแก้ไข ให้สรุปเป็น checklist ใน Issue แล้วใช้สถานะ “ต้องแก้ไขตามความคิดเห็น”
4. เมื่อได้รับอนุมัติจริง บันทึกวันที่และผู้ตรวจ อัปเดตทะเบียนทั้งสองไฟล์ แล้วปิด Issue
